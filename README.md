# Anime Images Database

A SQLite database containing metadata for a collection of anime images, including file information, tags, and source references.

> ⚠️ **Disclaimer**: This database stores only metadata (file URLs, sizes, hashes, dimensions, tags, and source references). No image files are included. All images belong to their respective original artists and copyright holders.

## Overview

This project provides a structured SQLite database for organizing anime image collections. It is designed for use in personal gallery tools, tagging systems, image viewers, or any application that needs to index and search anime artwork by tags, authors, or sources.

## Database Schema

The database consists of four tables:

### `images`
Stores core metadata for each image.

| Column | Type | Description |
|--------|------|-------------|
| `id` | INTEGER | Primary key |
| `file_url` | TEXT | URL to the image file (not null) |
| `file_size` | INTEGER | File size in bytes (not null) |
| `md5` | TEXT | MD5 hash, unique identifier (not null) |
| `width` | INTEGER | Image width in pixels (not null) |
| `height` | INTEGER | Image height in pixels (not null) |
| `author` | TEXT | Artist/author name |
| `source` | TEXT | Source URL (e.g., Pixiv link) |
| `has_children` | BOOLEAN | Whether the image has child/variant images (not null) |

### `tags`
Stores unique tag names.

| Column | Type | Description |
|--------|------|-------------|
| `id` | INTEGER | Primary key, auto-increment |
| `name` | TEXT | Tag name, unique (not null) |

### `image_tags`
Junction table linking images and tags (many-to-many).

| Column | Type | Description |
|--------|------|-------------|
| `image_id` | INTEGER | Foreign key → `images.id` (CASCADE on delete) |
| `tag_id` | INTEGER | Foreign key → `tags.id` (CASCADE on delete) |
| *(composite)* | — | Primary key (`image_id`, `tag_id`) |

### `sqlite_sequence`
Auto-generated by SQLite for tracking `AUTOINCREMENT` values.

## Entity Relationships

```
images ──< image_tags >── tags
```

- One image can have many tags.
- One tag can belong to many images.
- Deleting an image or tag automatically removes the corresponding rows in `image_tags`.

## Usage Examples

### Open the database

```bash
sqlite3 anime_images.db
```

### Find images by tag

```sql
SELECT i.file_url, i.author, i.source
FROM images i
JOIN image_tags it ON i.id = it.image_id
JOIN tags t ON t.id = it.tag_id
WHERE t.name = 'long_hair'
LIMIT 20;
```

### Count images per tag

```sql
SELECT t.name, COUNT(*) AS image_count
FROM tags t
JOIN image_tags it ON t.id = it.tag_id
GROUP BY t.name
ORDER BY image_count DESC
LIMIT 10;
```

### Get all tags for a specific image

```sql
SELECT t.name
FROM tags t
JOIN image_tags it ON t.id = it.tag_id
WHERE it.image_id = 42;
```

### Search images by author

```sql
SELECT id, file_url, source
FROM images
WHERE author LIKE '%RyuZU%';
```

### Detect duplicate images (by hash)

```sql
SELECT md5, COUNT(*) AS copies
FROM images
GROUP BY md5
HAVING copies > 1;
```

## Potential Use Cases

- **Personal gallery manager** — browse, filter, and search your collection.
- **Tag-based recommender** — suggest similar images using tag co-occurrence.
- **Deduplication tool** — use the `md5` column to detect duplicates.
- **Dataset for ML** — pair with an image downloader to build a tagged dataset.
- **Source tracker** — keep track of original artists and Pixiv/source URLs.

## Notes & Recommendations

- Image URLs may become unavailable over time; consider caching thumbnails or storing local paths.
- Tag names follow typical booru-style conventions (e.g., `long_hair`, `blue_eyes`, `1girl`).
- The `md5` column is a reliable unique key for deduplication.
- For large collections, add indexes on frequently queried columns:
  ```sql
  CREATE INDEX idx_images_author ON images(author);
  CREATE INDEX idx_images_md5 ON images(md5);
  CREATE INDEX idx_tags_name ON tags(name);
  ```
